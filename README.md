# Mini Paint 1.0

서버·계정 없이 브라우저에서 실행하는 경량 레이어 그림판입니다. Canvas 2D와 Pointer Events를 사용하며 런타임 외부 의존성이 없습니다. Windows의 최신 Chrome/Edge에서 사용하도록 설계했습니다.

## 개발과 배포

Node.js 22.12 이상(이 환경에서는 24.22.1)을 사용합니다.

```sh
npm ci
npm run dev
```

```sh
npm run build
npm run preview
npm test
```

`npm test`는 시스템 Chromium(`/usr/bin/chromium`)을 사용합니다. 다른 위치는 `CHROMIUM_PATH`로 지정하세요. Chromium이 없다면 Playwright 공식 브라우저 설치 후 해당 실행 파일 경로를 지정할 수 있습니다. 테스트가 개발/프로덕션 서버를 직접 시작합니다. 먼저 `npm run build`가 필요합니다.

Cloudflare Pages 빌드 명령은 `npm run build`, 출력 디렉터리는 `dist`입니다. 별도 API·환경 변수·인증 키가 필요하지 않습니다. 정적 서버를 통해 실행하며 HTML을 `file://`로 직접 여는 방식은 지원하지 않습니다. 최초 온라인 방문 후 서비스 워커 설치가 완료되면 프로덕션 앱을 오프라인에서도 다시 열 수 있습니다. 개발 서버에는 오프라인 캐시를 적용하지 않습니다.

## 사용

- 펜·지우개·화면 이동: **B / E / H**. **Space + 드래그** 또는 마우스 가운데 버튼으로 이동합니다.
- 브러시 크기 **[ / ]**, 1–100px. 색상과 스트로크 불투명도를 조절합니다. 필압과 보정은 적용하지 않습니다.
- 확대·축소 10–800%: 하단 버튼, **Ctrl + + / −**, **Ctrl + 휠**. **Ctrl + 0**으로 맞춥니다.
- 실행 취소 **Ctrl + Z**, 다시 실행 **Ctrl + Y / Ctrl + Shift + Z**.
- 새 작업 **Ctrl + N**, 열기 **Ctrl + O**, 저장 **Ctrl + S**, 다른 이름으로 저장 **Ctrl + Shift + S**.
- 레이어를 선택하고 이름을 더블클릭해서 바꿉니다. 눈 아이콘으로 숨기고, 화살표로 위아래 이동합니다. **Delete**는 선택 레이어의 픽셀을 지웁니다.
- PNG는 새 레이어로 가져옵니다. 큰 이미지는 비율을 유지하며 현재 캔버스에 맞게 축소합니다.
- PNG 내보내기에서 투명·흰 배경을 고릅니다. 우측의 흰 배경 보기는 화면 표시만 바꿉니다.
- 좌측 하단 진단 버튼은 렌더 소요 시간, 입력 처리부터 렌더 완료까지의 시간, 히스토리 사용량을 표시합니다. 하드웨어·디스플레이의 실제 입력 지연이나 FPS 보장값이 아닙니다.

## 파일과 복구

`.mpaint`는 버전 1 JSON으로 캔버스 크기, 이름, 아래→위 레이어 순서, 각 레이어의 이름·표시 여부·불투명도·PNG 데이터 URL을 담습니다. File System Access API 지원 브라우저에서는 파일 선택 후 직접 저장하고, 미지원 환경에서는 다운로드합니다. 일반 파일 열기는 새 다운로드 또는 저장 위치 선택으로 저장합니다. 다운로드 완료 여부는 브라우저에서 확인하세요. 쓰기 권한 오류를 성공으로 표시하지 않습니다.

일부 이전 JSON 형태(`canvasWidth/canvasHeight`, 레이어의 `dataURL` 또는 `data` PNG 필드, 버전 생략)를 읽을 수 있습니다. 제공된 원본은 `tests/fixtures/mini_paint_layers.html`에 보관했습니다. 원본 앱이 실제로 저장한 `version: 1`, `width/height`, `layers[].data` 형식의 JSON을 새 앱에서 열어 픽셀·레이어 순서·이름·표시 여부를 보존하는 브라우저 회귀 테스트를 추가했습니다. 원본에 없는 레이어 불투명도는 100%로 읽습니다.

편집을 멈춘 뒤 약 1.2초 후 IndexedDB에 마지막 작업을 저장합니다. 다음 접속에서 복구 여부를 묻습니다. 자동 복구는 현재 브라우저·사이트 주소에 한정하며, 프로젝트 파일 저장을 대신하지 않습니다. 저장 공간 부족·브라우저 데이터 삭제·시크릿 모드에는 보장되지 않습니다. 명시적 파일 저장을 하지 않았거나 자동 저장이 완료되지 않으면 페이지 이탈 시 경고를 요청합니다(실제 표시는 브라우저 정책에 따릅니다).

## 구현 구조와 안정성

- `src/engine.ts`: 독립 레이어 Canvas, 브러시 마스크 합성, 픽셀 명령 히스토리, 프로젝트 검증·직렬화.
- `src/main.ts`: DOM UI, 좌표 변환, 포인터 캡처, 단축키, 파일 API, IndexedDB, 진단.
- `src/style.css`: 고정 툴바·우측 레이어 패널과 작은 화면 레이아웃.
- `public/sw.js`: 프로덕션 정적 앱의 오프라인 캐시.
- `tests/paint.spec.ts`: 브라우저 기능·픽셀 회귀 검사.

스트로크마다 원본·마스크 Canvas를 임시 보유하고, 프레임당 변경된 타일만 다시 합성합니다. 같은 스트로크가 겹쳐도 불투명도가 누적되지 않습니다. 히스토리에는 바뀐 128×128 픽셀 타일의 이전·이후 ImageData만 남깁니다. 지우개 역시 알파를 복원합니다. 포인터 취소·캡처 상실·창 포커스 상실은 진행 중인 획을 취소합니다. Undo/Redo는 동기 픽셀 연산이며, 작업 중 구조 변경·다중 포인터 입력을 차단합니다.

히스토리는 최대 50개 명령·128 MiB입니다. 레이어 추가/삭제 명령이 유지하는 Canvas도 보수적으로 메모리 계산에 포함합니다. 상한을 넘으면 오래된 기록을 제거하고 안내합니다. 이 한도는 앱 전체 메모리 한도가 아닙니다. 현재 레이어, 렌더 Canvas, 임시 버퍼, 직렬화/가져오기 버퍼는 별도입니다. 캔버스는 각 변 1–4096px, 레이어는 최대 50개 및 총 128백만 픽셀로 제한합니다. 기본 크기는 1600×1200입니다. 프로젝트 파일 한도 128 MiB, 가져올 PNG 한도 64 MiB입니다.

프로젝트는 모든 레이어를 검증·디코딩한 뒤 한 번에 교체합니다. 실패 시 기존 작업을 유지합니다. 파일·자동 저장은 동기적으로 캡처한 동일 리비전의 Canvas에서 비동기 PNG 인코딩하며, 이후 편집과 구분해서 저장 상태를 표시합니다.

## 검증 범위

자동 테스트는 Chromium에서 실제 마우스 이벤트로 점 100회·작은 원 100회·빠른 지그재그, 30회 Undo/Redo, 20개 레이어, 펜/지우개, 확대 좌표, 취소 처리, 프로젝트/PNG, 복구, 오프라인 실행을 검사합니다. 합성 이벤트 검사는 실제 타블렛 드라이버·Windows 하드웨어 검증을 대신하지 않습니다. Windows Chrome/Edge 및 실제 마우스·타블렛에서 작은 원, 포인터 캡처, 파일 쓰기 권한, 장시간 메모리 사용을 별도로 확인해야 합니다. 측정 없이 특정 FPS나 지연시간을 보장하지 않습니다.

레이어 ID는 앱 내부의 증가하는 카운터로 만들기 때문에 `crypto.randomUUID()`가 없는 HTTP 접속 환경에서도 드로잉 엔진이 시작됩니다. 단, 서비스 워커 오프라인 실행과 File System Access API는 브라우저의 보안 컨텍스트 정책에 따르므로 HTTPS 또는 localhost가 필요합니다.
