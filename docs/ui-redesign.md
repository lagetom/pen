# 작업 화면 재구성 (UI/UX)

`main` `07fdddd` 기준. 기능·단축키·파일 형식·브러시 엔진은 그대로 두고 화면 구조만 다시 짰습니다. 새 런타임 의존성은 없습니다.

## 이전 화면의 문제

| 영역 | 문제 |
| --- | --- |
| 상단 | 로고 줄(66px) + 파일 줄(55px) + 옵션 줄(57px) + 선택 영역 줄(약 36px)이 항상 쌓여 캔버스 위 210px 이상을 차지 |
| 옵션 줄 | 페인트통·질감 브러시를 고르면 줄바꿈으로 높이가 변해 캔버스가 밀림. 선택 영역 버튼 7개는 도구와 무관하게 상시 노출 |
| 도구 모음 | 아이콘만 있는 버튼 13개. 펜·연필·잉크펜·싸인펜·볼펜 아이콘이 서로 비슷함 |
| 우측 패널 | 브러시 미리보기·팔레트·작업 화면 설정이 펼쳐진 채 레이어 목록 높이를 나눠 씀 |
| 컷 패널 | 132px 고정. 한 컷만 그릴 때도 접을 수 없음 |
| 캔버스 위 | 캔버스 라벨·조작 안내·확대 컨트롤이 작업 공간 위에 떠 있음 |

## 새 구조

```
┌ 메뉴 막대 36px ─ 파일 · 편집 · 보기 · 레이어 · 설정 │ 문서 이름 │ 실행 취소 · 다시 실행 · 저장 · 내보내기 ┐
├ 도구 ┬ 도구 설정 막대 40px (선택한 도구의 설정만) ───────────────┬ 레이어 패널 ┤
│ 레일 │ 캔버스                                                   │  목록이 남는 │
│ +색상│                                                          │  높이를 전부 │
│      ├ 컷 패널 (접기 · 높이 조절) ───────────────────────────────┤  사용        │
│      ├ 상태 막대 26px ─ 상태 · 좌표 · 크기 · 자동 저장 · 반전 · 확대 ┤ 종이 가이드 ▸│
└──────┴──────────────────────────────────────────────────────────┴──────────────┘
```

1440×1000 창에서 캔버스 영역 높이는 약 623px → 약 776px, 화면 맞춤 배율은 44% → 57%입니다(1600×1200 캔버스 기준).

- **메뉴 막대**: 모든 명령을 다섯 메뉴에 모았습니다. 단축키를 항목 오른쪽에 표시합니다. 자주 쓰는 실행 취소·다시 실행·저장·내보내기는 막대에 버튼으로 남겼습니다. 메뉴는 열릴 때만 항목의 활성 상태를 읽습니다.
- **도구 레일**: 그리기 / 선택·이동 / 보조 세 묶음으로 나누고 이름과 단축키를 함께 표시합니다. 모든 도구는 한 번의 클릭으로 선택합니다. 선택한 도구는 강조색 배경으로 표시합니다. 창 너비 1180px 미만이거나 **보기 → 도구 이름 표시**를 끄면 아이콘만 남습니다(44px). 전경색·배경색·교환·초기화·팔레트를 레일 아래에 모았습니다.
- **도구 설정 막대**: 높이가 고정된 한 줄입니다. 왼쪽 선택 상자가 현재 도구 이름을 보여 주며 도구 전환도 됩니다.

  | 도구 | 표시하는 설정 |
  | --- | --- |
  | 펜·연필·진한 연필·지우개 | 크기, 불투명도, 도구 세트 |
  | 거친 잉크펜·싸인펜·볼펜 | 크기, 불투명도, 질감, 도구 세트 |
  | 페인트통 | 불투명도, 허용 오차(슬라이더+숫자), 확장, 인접 영역, 참조 레이어 |
  | 사각형 선택 | 자유 변형, 전체 선택, 선택 해제, 복사, 잘라내기, 붙여넣기, 지우기 |
  | 레이어 이동 | 자유 변형 |
  | 전체 그림 이동 | 숨긴 레이어 포함 |
  | 스포이트·화면 이동 | 없음 |

  자유 변형 중에는 변형 수치 막대가 같은 자리를 대신합니다. 폭이 좁으면 슬라이더가 먼저 줄고, 더 좁으면 숫자 입력만 남습니다.
- **레이어 패널**: 제목·도구 줄·불투명도 아래 남는 높이를 모두 목록이 씁니다. 활성 레이어는 강조색 세로 막대와 배경, 굵은 이름으로 표시합니다. 숨긴 레이어는 눈 아이콘과 흐린 썸네일로 구분합니다. **작업 화면 · 종이 가이드**는 접이식이며 기본은 접힌 상태입니다.
- **컷 패널**: 왼쪽 ▾ 버튼 또는 **보기 → 컷 목록 표시**로 접습니다. 위쪽 경계를 끌거나 포커스 후 ↑/↓로 96–320px 범위에서 높이를 조절합니다. 썸네일은 높이에 맞춰 커집니다.
- **상태 막대**: 보기 좌우 반전과 확대·축소·화면 맞춤을 캔버스 밖으로 옮겼습니다.

## 저장하는 화면 설정

| 키 | 내용 |
| --- | --- |
| `mini-paint-layer-panel-v1` (기존) | 패널 너비, 접힘, 행 높이, 종이 가이드 구획 열림. 기존 값은 그대로 읽습니다. 저장된 값이 없을 때의 가이드 구획 기본값만 닫힘으로 바뀌었습니다. `brush` 필드는 더 쓰지 않지만 읽고 보존합니다 |
| `mini-paint-workspace-v1` (신규) | 컷 패널 높이·접힘, 도구 이름 표시 선택 |

도구별 설정(`mini-paint.tool-settings.v1`), 사용자 프리셋, `.mpaint` 형식, IndexedDB 복구 데이터는 건드리지 않았습니다.

## 기능 접근 경로

기존 컨트롤의 `id`와 동작은 유지했습니다. 위치가 바뀐 것만 정리합니다.

| 기능 | 이전 | 현재 |
| --- | --- | --- |
| 새 캔버스 · 열기 · 이미지 가져오기 | 파일 줄 버튼 | 파일 메뉴 (Ctrl+N / Ctrl+O 유지) |
| 다른 이름으로 저장 | 단축키만 | 파일 메뉴 + Ctrl+Shift+S |
| 환경 설정 · 브러시 테스트 · 사용법 · 성능 진단 | 상단·좌측 하단 버튼 | 설정 메뉴 |
| 선택 영역 작업 | 상시 노출 줄 | 사각형 선택 도구의 설정 막대 + 편집 메뉴 + 단축키 |
| 숨긴 레이어 포함 | 상시 노출 줄 | 전체 그림 이동 도구의 설정 막대 |
| 보기 반전 · 확대 · 화면 맞춤 | 옵션 줄 / 캔버스 위 | 상태 막대 + 보기 메뉴 + 단축키 |
| 팔레트 · 색상 | 우측 패널 / 레일 | 레일 아래 |
| 레이어 명령 | 패널 하단 두 줄 | 패널 상단 도구 줄 + 하단 한 줄 + 레이어 메뉴 |

제거한 것은 장식·중복 표시뿐입니다: 로고 장식과 버전 표기, "내 기기에만 저장" 배지, 브러시 미리보기 카드(이름·크기는 설정 막대에 있음), 캔버스 위 조작 안내, 대화상자 아이콘.

## 드로잉 경로

브러시 엔진(`engine.ts`, `pencil.ts`, `basic-brushes.ts`)은 수정하지 않았습니다. 입력 경로에서 UI가 하던 일을 줄였습니다.

- 포인터 이동마다 좌표 글자와 브러시 커서의 `left/top`을 쓰던 것을 프레임당 한 번, `transform`으로 바꿨습니다. 이전에는 이 쓰기가 레이아웃을 무효화해, 같은 이벤트의 좌표 계산(`getBoundingClientRect`)이 매번 레이아웃을 다시 수행했습니다.
- 컷 목록은 UI 갱신마다 모든 카드를 새로 만들던 것을 컷 id 기준으로 재사용하고 바뀐 속성만 씁니다. 획 하나에 UI 갱신이 세 번 이상 일어나므로 짧은 획일수록 효과가 큽니다.
- 레이어 행은 마지막으로 쓴 이름·불투명도·표시·활성 상태를 기억해 같은 값은 다시 쓰지 않습니다.
- 종이 가이드 오버레이 스타일은 설정이 바뀔 때만 다시 씁니다.
- 도구 전환은 이전·다음 도구 버튼 두 개만 갱신합니다.
- 전환·애니메이션·그라데이션·블러는 쓰지 않습니다.

## 검증

Linux 클라우드 환경의 Chromium(Playwright 번들 1243)에서 실행했습니다. Windows·실제 타블렛 결과가 아닙니다.

- `npm run build`: 타입 검사·프로덕션 빌드·서비스 워커 생성 성공. JS 125.18 kB(gzip 41.34 kB), CSS 21.49 kB(gzip 5.19 kB).
- 최종 전체 회귀 1회: **90개 중 87개 통과**(약 2.3분). 기존 84개 + 신규 6개(`tests/workspace.spec.ts`). 반복 부하는 기존 25% 정책 그대로이며 저장·복구·PSD·오프라인 검사는 줄이지 않았습니다.
- 실패 3개는 변경 전 `main` `07fdddd`에서도 이 환경에서 동일하게 실패합니다: `paint.spec.ts` "프로젝트 다운로드 및 PNG 내보내기 UI", `productivity.spec.ts` "PSD Worker 생성…", "PSD 라이브러리 지연 로딩…". 이 환경의 Chromium이 blob 다운로드의 `suggestedFilename()`을 `download`로 보고하기 때문이며, 파일명 단언만 임시로 완화해 실행하면 세 테스트 모두 통과합니다(프로젝트 저장, PNG, PSD 재파싱·DPI, 오프라인 재사용 검증 포함). 완화한 사본은 커밋하지 않았습니다. 저장 경로(`download()`, `save()`) 코드는 수정하지 않았습니다.
- 신규 검사: 메뉴 열기·닫기·대상 상태 반영·명령 실행, 다른 이름으로 저장 메뉴, 13개 도구별 설정 표시와 막대 고정 높이(캔버스 위치 불변), 컷 패널 접기·높이·범위·취소·복원, 손상된 화면 설정 복구, 획을 그리는 동안 작업 화면 DOM 변경이 좌표 글자·브러시 커서뿐인지와 컷 카드·레이어 행 재사용.
- 기존 테스트 수정은 접근 경로뿐입니다: 메뉴로 옮긴 `새 캔버스`·`환경 설정`·`브러시 테스트`는 메뉴를 열어 클릭, 가이드 컨트롤을 쓰는 테스트는 구획을 먼저 펼침, 패널 설정 복원 테스트는 제거한 브러시 구획 대신 가이드 구획의 기본 닫힘과 열림 복원을 확인.

입력 지연은 이 환경에서 신뢰할 만한 전후 비교 수치를 얻지 못해 수치로 주장하지 않습니다. 위 DOM 변경 검사가 구조적 근거이며, 실제 체감은 Windows Chrome/Edge와 타블렛에서 **설정 → 성능 진단**으로 확인해야 합니다.
