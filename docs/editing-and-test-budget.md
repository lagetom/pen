# 반전·레이어 편집·테스트 경량화

작업 브랜치는 `feat/mini-paint-v1`입니다. 작업 시작 시 기존 기능이 main에 병합된 `604cb7a`까지 이 브랜치만 fast-forward했습니다. main에는 직접 쓰지 않습니다.

## 구현 기능

- **M / 보기 좌우 반전 버튼**: 현재 작업 화면을 좌우 반전합니다. CSS 표시 변환에만 적용하며, 픽셀·레이어·히스토리·프로젝트 파일·PNG/PSD 출력은 변경하지 않습니다. 모든 레이어와 종이 가이드가 같은 변환을 받습니다. 화면 좌표를 원본 캔버스 좌표로 역변환하므로 반전 상태에서도 펜·연필·지우개·레이어 이동·스포이트가 같은 좌표계를 사용합니다. 확대는 포인터 기준, 화면 이동은 화면 기준으로 유지합니다. 반전은 세션의 보기 상태이며 파일에 저장하지 않습니다. 숫자/텍스트 입력 중에는 M이 발동하지 않고 키 반복으로 연속 토글하지 않습니다.
- **레이어 좌우 반전**: 우측 레이어 도구에서 선택 레이어의 실제 RGBA 픽셀 순서를 뒤집습니다. 한 개의 Undo/Redo 명령이며 다른 레이어와 컷을 바꾸지 않습니다. 빈 레이어나 픽셀이 같은 결과는 불필요한 명령을 만들지 않습니다.
- **레이어 복제**: 선택 레이어 위에 독립 복사본을 추가하고 선택합니다. 이름·표시·불투명도·픽셀을 보존하고 추가 작업을 Undo/Redo할 수 있습니다. 기존 50개/128백만 픽셀 제한을 적용합니다.
- **V / 레이어 이동**: 보이는 선택 레이어를 드래그해 정수 픽셀 단위로 이동합니다. 원본에서 프레임당 한 번 미리보기를 그리며 드래그 전체를 한 명령으로 확정합니다. pointercancel·캡처 상실·Escape·창 포커스 상실은 원본으로 복원하고 히스토리를 소비하지 않습니다. **확정 시 캔버스 밖 픽셀은 잘리며 Undo로 복구할 수 있습니다.** 비파괴 객체 이동은 아닙니다.
- **I / 스포이트**: 보이는 레이어가 합성된 원본 뷰포트의 색을 읽고 이전 브러시로 돌아갑니다. 가이드·체크무늬·화면 표시용 흰 배경은 제외합니다. 투명 픽셀은 색을 바꾸지 않고 안내합니다. 브러시 크기·불투명도와 그림 히스토리는 바꾸지 않습니다. 별도 1px 캔버스로 재합성할 때 발생할 수 있는 반올림 차이를 피하기 위해, 밀린 화면 렌더를 반영한 다음 이미 생성한 합성 버퍼의 픽셀을 읽습니다.

선택 영역은 아직 없으므로 실제 반전은 레이어 전체에 적용합니다. 선택 영역·대칭 그리기·참고 이미지·텍스트/말풍선은 다음 단계로 남깁니다. 새 외부 의존성은 추가하지 않았습니다.

## 변경 파일

| 파일 | 역할 |
| --- | --- |
| `src/view-transform.ts` | 표시 반전과 포인터 역변환. 픽셀/히스토리와 분리 |
| `src/layer-edits.ts` | 레이어 반전·복제·드래그 이동과 픽셀 명령 |
| `src/eyedropper.ts` | 합성 뷰포트의 1픽셀 읽기 |
| `src/main.ts` | 버튼·M/I/V·기존 Pointer Events/캡처 연결 |
| `src/style.css` | 레이어 편집 버튼과 도구 표시 |
| `tests/editing.spec.ts` | 새 기능의 기능·픽셀·취소·파일 격리 검사 |
| `tests/paint.spec.ts` | 펜/Undo/레이어 반복 부하 축소 |
| `tests/pencil-guides.spec.ts` | 연필 반복 및 분할 경로 길이 축소 |
| `tests/storyboard.spec.ts` | 컷·레이어 반복 부하 축소 및 복원 유지 |
| `README.md`, `VALIDATION.md`, `docs/pencil-paper-guides.md`, 이 문서 | 현재 사용법·테스트 정책·실행 결과 |

기존 Canvas 2D 브러시 엔진은 수정하지 않았습니다. 픽셀 편집 모듈은 공개 `Paint.commit/structure`와 `Command.layers`를 사용하므로 기존 Undo/Redo와 컷 압축/복원 정책에 연결됩니다. 스트로크 경로에 새 필터나 무작위 처리를 추가하지 않습니다.

## 테스트 실행량

| 반복 부하 | 이전 | 현재 |
| --- | --- | --- |
| 펜·연필 점 | 각 100 | 각 25 |
| 펜·연필 작은 원 | 각 100 | 각 25 |
| 반복 Undo/Redo | 각 30 | 각 8 |
| 레이어 수 | 20 | 5 |
| 빠른 지그재그 | 80 | 20 |
| 펜/지우개 전환 | 10 | 3 |
| ID 생성 반복 | 100 | 25 |
| 연필 분할 경로 샘플 | 180 | 45 |
| 캐시 해제 컷 수 | 8 | 4 (기능 검증 최소) |

원의 형태를 유지할 12개 경로 좌표, 데이터/파일 저장·복원, 픽셀 격리, 오류·취소, PSD 검사, 포맷 경계의 50개 **8×8px** 레이어 검사는 유지합니다. 캐시가 최대 3개 컷을 상주시키므로 해제/재로딩 검사에는 최소 4개 컷이 필요합니다. 레이어 캐시 검사는 5개 레이어에서 예산과 보존을 확인하며, 이전 20개 레이어의 대용량 상한 스트레스 강도를 주장하지 않습니다. 앱 자체의 히스토리 50단계·메모리 제한은 바꾸지 않았습니다.

개발 중에는 관련 테스트 파일/케이스만 실행하고, 구현이 끝나면 전체 회귀를 한 번 실행합니다.

```sh
npm test -- tests/editing.spec.ts
npm test -- tests/editing.spec.ts --grep '스포이트'
npm run build
npm test
```

이번 작업에서는 새 기능의 관련 검사 7개를 먼저 실행했고, 발견한 스포이트 반올림 차이 수정 후 그 검사만 재실행했습니다. 이후 최종 빌드와 전체 회귀를 한 번 실행하여 49개가 통과했습니다(약 1분). 반복 부하는 약 25%로 줄였지만 파일 I/O·자동 저장 등의 기능 검사는 유지하므로 전체 실행 시간이 정확히 25%가 된다고 보장하지 않습니다.
