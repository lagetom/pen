# UI·작업 프리셋·PSD

작업 브랜치: `feat/mini-paint-v1`. 기존 인스타툰·연필·가이드 기능을 보존하기 위해 시작 시 main의 `98d6b31`까지 이 브랜치만 fast-forward했습니다. main에는 직접 쓰지 않습니다.

## UI 및 숫자 입력

장식 문구와 sidebar-note 요소, 브러시의 장식 설명을 제거했습니다. 브러시 설정·사용법·새 캔버스처럼 기능 이름으로 표시하며, 오류·저장·복구 안내는 유지합니다.

브러시 크기/불투명도, 레이어 불투명도, 가이드 간격/진하기는 슬라이더와 숫자를 양방향 연결했습니다. 빈 값·소수·잘못된 숫자는 모델에 적용하지 않습니다. 범위를 벗어난 정수는 최소/최대값으로 제한합니다. 필드를 떠나면 미완성 값은 마지막 유효값으로 복원합니다. 숫자 필드의 단축키는 앱 드로잉 동작으로 전달하지 않습니다. 레이어 불투명도는 change/포커스 종료에서 확정해 한 번의 변경을 하나의 Undo 명령으로 처리합니다. 진행 중인 스트로크는 시작 시 캡처한 크기·불투명도를 계속 사용하고 새 브러시 값은 다음 획에 적용됩니다.

## 크기·인쇄 해상도

기본 단위는 px이며 새 캔버스 대화상자에서 mm와 DPI, 가로/세로 방향을 지정합니다.

| 프리셋 | 픽셀 크기 | DPI |
| --- | --- | --- |
| A4 150 | 1240×1754 | 150 |
| A4 300 | 2480×3508 | 300 |
| A5 150 | 874×1240 | 150 |
| A5 300 | 1748×2480 | 300 |
| 인스타툰 4:5 | 1080×1350 | 96 |
| 인스타툰 3:4 | 1080×1440 | 96 |
| 정사각형 | 1080×1080 | 96 |

기존 1600×1200, 1920×1080, 1200×1200, 1080×1920과 사용자 지정도 유지합니다. DPI는 36–1200 정수입니다. mm 입력은 `round(mm / 25.4 × DPI)`로 변환합니다. px 입력에서 DPI 변경은 픽셀 수를 바꾸지 않고 인쇄 크기만 바꿉니다. mm 입력에서 DPI 변경은 물리 크기를 유지하고 픽셀 수를 다시 계산합니다. 반올림 때문에 픽셀에서 환산한 mm는 명목상 A4/A5 크기와 조금 다를 수 있습니다.

각 변 1–4096px, 컷당 최대 50개 레이어·합계 128백만 픽셀, 기존 히스토리/상주 메모리 제한은 유지합니다. 크기가 한도를 초과하면 캔버스를 만들지 않고 이유를 표시합니다.

`.mpaint` v1 및 v2에 선택 필드 `dpi`를 저장합니다. v2는 프로젝트 공통 DPI이며 모든 컷에서 같은 크기·DPI를 사용합니다. DPI 필드가 없는 이전 파일은 96으로 읽고, 잘못된 메타데이터는 현재 작업을 교체하지 않고 거부합니다.

PNG는 리샘플링하지 않으므로 원본 픽셀 수를 유지합니다. ‘DPI 메타데이터 포함’을 선택하면 PNG pHYs 청크에 `round(DPI / 0.0254)` pixels/meter를 기록합니다. 선택하지 않으면 기존 Canvas PNG를 그대로 다운로드합니다. DPI 메타데이터를 기록해도 실제 이미지의 픽셀 수는 바뀌지 않으며, 인쇄 프로그램의 배율 설정은 별도입니다.

## 사용자 프리셋

환경 설정에서 현재 설정을 이름과 함께 추가하고 이름 변경·삭제·적용할 수 있습니다.

- 브러시: 펜/연필/진한 연필/지우개, 크기, 불투명도, 색상, 연필 질감 스키마 버전.
- 작업: 현재 캔버스 크기·DPI·종이 가이드·흰 배경 표시 설정. 적용하면 새 빈 프로젝트를 만듭니다. 저장하지 않은 현재 작업은 기존 교체 확인을 거칩니다.

브라우저 localStorage의 별도 키에 최대 100개를 저장하며 프로젝트 픽셀 데이터·히스토리·파일 핸들을 포함하지 않습니다. JSON 형식은 `{format:'mini-paint-presets',version:1,presets:[...]}`입니다. 가져오기는 최대 256 KiB이며 전체 항목을 검증한 뒤 기존 목록에 추가하고 새 ID를 부여합니다. 잘못된 항목·버전·중복 ID·범위 초과는 기존 목록을 유지하며 거부합니다. localStorage 쓰기 실패도 안내합니다. 브라우저 데이터 삭제 시 프리셋도 사라지므로 JSON 백업을 권장합니다.

## PSD

PNG 내보내기 대화상자의 ‘PSD 저장’은 **현재 컷**만 내보냅니다. `.mpaint`는 계속 편집·복구용 파일로 유지합니다. PSD 가져오기는 구현하지 않습니다.

- `ag-psd` 34.1.0, RGB 8bit.
- 래스터 레이어를 아래→위 순서대로 전달합니다. 이름·숨김·불투명도·각 레이어의 RGBA 픽셀을 보존합니다.
- 별도 합성 이미지와 DPI resolutionInfo를 포함합니다. 합성은 보이는 레이어만 사용하고 종이 가이드·화면 표시용 흰 배경은 제외합니다.
- PSD는 불투명도를 8bit(1/255 단계)로 표현합니다. 예를 들어 50%는 재파싱 시 약 50.196%가 됩니다. 이는 파일 형식의 양자화이며 임의의 실수값을 무손실 보존한다고 보장하지 않습니다.
- `src/psd-export.ts`는 버튼을 누를 때 dynamic import합니다. `ag-psd`는 별도 Worker 안에서 실행하며 초기 앱 JS에 포함되지 않습니다. 레이어를 프레임 사이에 복사하고 ArrayBuffer를 Worker로 이전합니다. 진행 상태·취소·오류를 표시합니다. 내보내기 중 프로젝트 편집은 잠가 같은 시점의 픽셀·속성을 사용합니다.
- 예상 추가 메모리 `(레이어 수 + 합성 1장) × 폭 × 높이 × 4 × 3`이 512 MiB를 넘으면 인코딩을 시작하지 않고 PNG 또는 레이어 축소를 안내합니다. 이는 보수적 추정이며 브라우저 전체 RAM의 보장 상한은 아닙니다. 실패·취소 시 Worker를 종료하고 원본 픽셀·히스토리를 유지합니다.
- 기본 PNG/드로잉은 최초 방문 후 오프라인에서 동작합니다. PSD 청크는 최초 내보내기 때 온라인으로 로드하며, 서비스 워커가 성공한 청크를 캐시해 이후 오프라인 재사용을 지원합니다. 첫 PSD 로드 전에 오프라인이면 오류를 안내하며 프로젝트는 유지합니다.

현재 편집 가능한 텍스트/말풍선 객체는 없습니다. PSD는 현재 래스터 레이어만 지원하며 완전한 편집 가능한 텍스트 호환성을 표시하지 않습니다. 해당 객체를 추가할 때는 렌더 결과를 레이어로 전달하는 확장이 필요합니다.

## 독립 호환성 확인

실제 브라우저 Worker로 만든 64×64 PSD를 ag-psd로 재파싱하고 GIMP 3.0.4에서 열었습니다. 한글 레이어 이름, 아래/위 순서, 숨긴 초록 레이어, 파랑 레이어의 약 50.196% 불투명도를 확인했습니다. GIMP에서 PNG로 다시 내보낸 합성 결과와 앱 PNG를 ImageMagick AE로 비교한 결과 다른 픽셀은 0개였습니다. ImageMagick의 독립 PSD 리더가 읽은 합성 이미지도 0개 차이였습니다. 이 결과는 테스트 파일의 검증이며 모든 Photoshop 버전·프로파일·임의 레이어 구성의 완전 호환을 보장하지 않습니다.

테스트 `PSD Worker 생성`은 `/tmp/mini-paint-compat.psd`와 `.png`를 생성합니다. GIMP 3 및 X11 화면이 있는 환경에서 `gimp -n -i -d -f --batch-interpreter=python-fu-eval -b "exec(open('scripts/validate-psd-gimp.py').read())" --quit`로 다시 열고 `/tmp/mini-paint-gimp.png`를 생성할 수 있습니다. 이 클라우드에서는 별도 임시 dummy Xorg 화면을 사용하고 검증 후 종료했습니다.
