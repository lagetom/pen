# 인스타툰 작업 기반 — 1·2단계

기준은 `feat/mini-paint-v1`의 `3b1ac294`입니다. 구현 브랜치는 `feat/instagram-storyboard`이며 `main`은 변경하지 않습니다.

## 최소 변경 설계

기존 `Paint`는 한 컷의 래스터 엔진으로 유지합니다. 브러시·좌표 변환·Pointer Events·타일 패치 Undo/Redo를 다시 작성하지 않습니다. 새 `Storyboard`는 컷의 순서·이름·선택·화면 위치·썸네일과 상주 정책을 관리합니다. DOM은 현재 컷의 `Paint`에 다시 연결하며, 저장·자동 복구의 입력만 프로젝트 단위 직렬화로 바꿉니다.

엔진에 추가한 것은 히스토리 명령의 참조 레이어 목록과 명시적 픽셀 버퍼 해제입니다. 히스토리가 참조하는 삭제된 레이어도 압축·복원 대상에 포함해야 삭제 취소가 유지됩니다. 스트로크 종료·취소 후 임시 원본·마스크 Canvas도 즉시 해제하며, 히스토리 클로저는 대상 레이어와 타일 패치만 참조합니다.

## 구현한 작업 환경

- 새 작업 프리셋: 1080×1080(1:1), 1080×1350(4:5), 1080×1440(3:4), 1080×1920(9:16). 기존 1600×1200, 1920×1080과 사용자 지정 크기를 유지합니다.
- 프리셋·사용자 지정 크기를 이 브라우저의 localStorage에 기억합니다. 새 작업 대화상자, 캔버스 라벨, 내보내기 대화상자에 해상도와 비율을 표시합니다.
- 작업 화면은 흰 배경이 기본입니다. 투명 보기로 전환할 수 있고, PNG 출력의 흰색/투명 선택은 별도로 유지합니다. 흰색을 래스터 픽셀에 넣지 않습니다.
- 하단 컷 목록에서 추가·복제·이름 변경·순서 이동·삭제·선택을 지원합니다. 썸네일은 최대 96×72px이며 편집 중 매 포인터 이벤트에서 만들지 않습니다.
- 컷마다 독립 레이어·선택 레이어·확대·이동·세션 내 히스토리를 유지합니다. 복제 컷은 독립 픽셀을 가지고 빈 히스토리로 시작합니다.
- 이전 컷의 모든 레이어를 현재 컷으로 복제할 수 있습니다. 이 작업은 현재 컷의 하나의 Undo 명령입니다.
- Ctrl+Z/Y는 현재 컷의 편집에만 작용합니다. 컷 추가·삭제·순서·이름은 프로젝트 구성 작업으로 분리했으며 이 단계에서는 Undo 대상이 아닙니다. 컷 삭제는 확인 후 수행합니다. 파일을 다시 열거나 자동 복구할 때는 기존처럼 히스토리를 복원하지 않습니다.

## Canvas 메모리와 전환 정책

현재 컷을 우선하고 바로 앞·뒤 컷만 캐시 후보로 삼습니다. 상주 컷은 최대 3개이고, 현재 컷과 이웃의 참조 레이어 픽셀 합이 32백만 픽셀(약 122 MiB) 이내일 때만 이웃을 상주시킵니다. 현재 컷 하나가 이 예산보다 크면 그 컷만 유지합니다. 한 컷의 기존 제한인 최대 50개 레이어·128백만 픽셀은 유지합니다. 컷은 최대 30개입니다.

비활성 컷은 각 참조 레이어를 PNG Blob으로 압축합니다. 모든 압축이 성공한 뒤 Canvas의 폭·높이를 0으로 만들어 실제 해상도 버퍼를 해제합니다. 다시 선택하면 모든 이미지를 먼저 디코딩하고 같은 Canvas/Layer 객체에 복원합니다. 이로써 기존 Undo/Redo 클로저가 다른 컷을 가리키거나 끊어지지 않습니다. 압축 실패 시 원본 버퍼를 먼저 지우지 않습니다.

히스토리의 타일 ImageData는 Canvas와 별도로 보존합니다. 전체 컷 합산 128 MiB를 넘으면 비선택 컷의 오래된 명령부터 정리하고 안내합니다. 컷별 최대 50단계도 유지합니다. 컷 전환은 비동기 잠금 중 입력을 받지 않으며, 백그라운드 저장은 모든 컷의 동일 시점 복사본/불변 Blob에서 수행합니다.

진단 패널은 상주 컷 수, 참조 Canvas의 바이트 수, 비활성 PNG Blob의 바이트 수, 전체 히스토리 바이트 수를 표시합니다. 이 값은 브라우저 프로세스 전체 RAM 측정이 아닙니다. 브라우저 이미지 디코더, view Canvas, 썸네일, 저장 스냅샷 및 인코딩 임시 버퍼는 추가 메모리를 사용합니다. 전환 중에는 다음 컷 디코딩 및 압축에 필요한 일시적 메모리가 생깁니다. 많은 컷의 전체 해상도 Canvas를 상시 보관하지는 않습니다.

## 파일 포맷과 실패 처리

새 저장 파일은 `.mpaint` version 2입니다.

```json
{
  "format": "mini-paint",
  "version": 2,
  "name": "인스타툰",
  "width": 1080,
  "height": 1350,
  "activeCut": "cut-2",
  "whiteBackground": true,
  "cuts": [
    {
      "id": "cut-2",
      "name": "컷 1",
      "activeLayer": 0,
      "view": {"zoom": 0.5, "panX": 50, "panY": 30},
      "layers": [{"name": "레이어 1", "visible": true, "opacity": 1, "image": "data:image/png;base64,..."}]
    }
  ]
}
```

모든 컷은 같은 캔버스 크기를 사용합니다. version 1 및 제공된 원본 HTML의 JSON은 기존 `Paint.decode`를 통해 1개 컷으로 변환합니다. 기존 파일을 자동으로 덮어쓰지 않으며 새 저장은 version 2입니다. version 2 파일은 구버전 앱에서 열리지 않습니다.

불러오기는 별도의 준비 프로젝트에서 컷을 순차 검증·압축한 뒤 현재 작업을 교체합니다. 잘못된 이미지, 중복 컷 ID, 선택 인덱스, 화면 위치, 미지원 버전은 거부하고 현재 그림을 유지합니다. 지원하지 않는 편집 객체가 있는 파일도 조용히 객체를 버리지 않고 거부합니다. 다운로드/직접 저장 파일은 128 MiB 이하입니다.

자동 복구는 기존 IndexedDB 저장소의 원자적 트랜잭션을 그대로 사용하며 version 1 복구 기록도 읽습니다. 실패한 저장으로 이전 복구 레코드를 부분 교체하지 않습니다. 파일 저장도 모든 컷 직렬화가 끝난 후 쓰기를 시작하고, 저장 도중 추가 편집은 미저장 상태로 남깁니다. 페이지 종료 경고·용량 오류 안내를 유지합니다.

## 다음 단계의 경계

이번 변경은 1단계와 2단계 기반입니다. 레이어 이동·크기 조절·클립보드, 수정 가능한 텍스트·말풍선, 전체 컷 PNG/ZIP 내보내기는 구현하지 않습니다. 현재 컷의 PNG 내보내기만 제공합니다.

다음 단계에서는 픽셀 레이어와 별도로 컷의 편집 객체 목록을 설계하고 텍스트/말풍선 객체의 위치·스타일·내용을 보존해야 합니다. 이를 래스터 레이어에 즉시 합치지 않습니다. 실제 한글 IME의 Enter/Escape/방향키 검증은 해당 편집 UI를 도입할 때 수행합니다. 현재는 기존 `isComposing` 및 텍스트 입력 중 단축키 차단 동작만 유지·검증합니다.
