# 도구 설정·도구 세트·RGB 반전·페인트통

기준: `main` `15fc7e36`, 작업 브랜치: `feat/toolsets-and-bucket`. 기존 Canvas 2D 브러시·자유 변형·선택·레이어·다중 컷·PSD 엔진을 유지했습니다. 외부 의존성 추가는 없습니다.

## 도구 설정과 색상

펜, 기본 연필, 진한 연필, 지우개는 독립적인 크기(1–100px)와 불투명도(0–100%)를 갖습니다. 기본 크기는 기존 펜/연필 값 8px를 유지하고 진한 연필 12px, 지우개 10px로 시작합니다. 각 도구로 돌아오면 마지막 값을 복원합니다. 슬라이더·숫자 입력·`[`/`]`는 활성 브러시 값만 바꾸며, 비브러시 도구에서는 크기 조절을 표시하지 않습니다. 진행 중인 획은 기존처럼 시작 시 캡처한 설정을 사용합니다.

전경색은 브러시 전체가 공유합니다. 별도 배경색은 색상 슬롯이며 표시용 흰 종이·프로젝트·레이어 픽셀과 분리합니다. **X** 또는 교환 버튼으로 전경/배경을 교환하고 기존 초기화 버튼으로 `#283747` / 흰색을 복원합니다. 지우개는 색상과 무관하게 알파를 지웁니다.

`mini-paint.tool-settings.v1`에 도구별 값·색상 슬롯·페인트통 옵션을 저장합니다. 새로고침 후 복원하며 그림 히스토리나 프로젝트 포맷에는 넣지 않습니다. 잘못된 저장 값은 기본값으로 복구하고 안내하며, 저장 공간 오류도 알립니다. 브라우저 데이터를 지우면 로컬 설정이 사라집니다.

## 도구 세트 프리셋

상단 **도구 세트** 메뉴와 환경 설정의 **도구 세트** 종류를 사용합니다. 일상툰 선화·작은 캐릭터·러프 스케치 예시를 제공하며 사용자도 추가·이름 변경·현재 값으로 덮어쓰기·삭제·적용할 수 있습니다. 환경 설정 표에서 네 도구의 크기·불투명도를 한눈에 보고 수정할 수 있습니다.

세트는 네 도구 설정과 전경/배경색을 저장합니다. 도구 세트와 단일 브러시 프리셋 적용은 현재 픽셀·캔버스·레이어·Undo 기록을 보존합니다. 기존 작업 프리셋은 그림 교체 확인 후 새 작업을 만드는 동작을 유지합니다. 페인트통 설정은 별도의 로컬 도구 설정으로 관리합니다.

- JSON `mini-paint-presets` **version 2**에 기존 `brush`/`work`와 새 `toolset`을 저장합니다. version 1의 기존 브러시·작업 파일도 읽습니다.
- 로컬 저장은 `mini-paint.user-presets.v2`를 사용하고, 최초 읽기에는 기존 `.v1` 키를 읽어 예시 세트를 더합니다. 원래 v1 저장 값은 지우거나 덮어쓰지 않습니다. v2가 생긴 뒤에는 사용자가 삭제한 예시를 다시 생성하지 않습니다.
- 읽기·가져오기 전체를 먼저 검증하고 한 번의 저장이 성공한 후 목록을 교체합니다. 이름/ID·중복 ID·크기·불투명도·색상·버전을 검사합니다. 기존 100개 및 가져오기 파일 256 KiB 제한을 유지합니다. 예시도 전체 개수에 포함됩니다.
- 프리셋 JSON에는 이미지 픽셀을 넣지 않으며 v2 파일을 이전 앱에서 읽을 수 있다고 표시하지 않습니다.

## RGB 색상 반전

레이어 패널의 **RGB 반전**을 누르면 활성 레이어 전체, 선택이 있으면 선택 사각형만 미리 봅니다. 적용/취소 또는 Escape를 제공합니다. 각 RGB 채널을 `255 - 값`으로 바꾸고 알파와 완전 투명 픽셀을 유지합니다. 미리보기 동안 자동 저장·다른 픽셀 편집을 막습니다. 취소는 원본 픽셀을 복원하고 적용은 하나의 Undo 명령을 만듭니다. 반투명 RGB는 Canvas의 8비트 알파 표현에 따른 정수 변환을 거칩니다.

## 페인트통

**G** 또는 왼쪽 도구 모음에서 선택합니다. 상단에서 불투명도·허용 오차(0–100)·확장(0–5px)·인접 영역·참조 범위를 설정합니다. 전경색을 사용해 실제 픽셀을 활성 레이어에만 기록합니다. 표시된 레이어를 선택해야 합니다.

- 인접 영역 기본 켜짐: 클릭한 픽셀과 연결된 **상하좌우** 영역을 찾습니다. 끄면 선택 범위 안에서 조건에 맞는 모든 픽셀을 찾습니다.
- 허용 오차는 알파 및 **RGB×알파** 채널의 최대 차이를 0–255 기준으로 판정합니다. 완전 투명 픽셀의 숨겨진 RGB는 영역을 나누지 않습니다. 0은 정확히 같은 보이는 RGBA, 100은 전체 범위를 허용합니다.
- 확장은 찾은 영역에서 **8방향으로 지정 픽셀 수만큼** 넓힙니다. 선택이 있으면 찾기·확장·기록 모두 선택 안으로 제한합니다. 선택 밖 클릭은 그림을 바꾸지 않습니다.
- 현재 레이어 또는 보이는 모든 레이어를 참조합니다. 참조용 합성에는 각 레이어의 표시/불투명도를 적용하며 종이 가이드·표시용 흰 배경·체크무늬를 넣지 않습니다. 숨긴 레이어는 제외합니다.
- 허용 오차와 확장으로 반투명/안티앨리어싱 경계를 조정할 수 있습니다. 확장은 경계 픽셀도 색칠합니다. 별도 빈 레이어에서 보이는 레이어를 참조하면 선화 레이어를 유지한 채 색칠할 수 있습니다.
- 색상은 현재 레이어 픽셀에 설정 불투명도로 source-over 합성합니다. 기존 반투명 픽셀의 RGB/알파도 함께 계산합니다. 0% 또는 결과가 같은 채우기는 히스토리를 만들지 않습니다.

영역 계산은 유한 크기 큐와 방문 마스크를 사용하고 각 픽셀을 중복 큐에 넣지 않습니다. 큰 계산은 약 8ms 작업 예산을 확인해 이벤트 루프에 양보하며 상태/진행률·취소 버튼과 Escape를 제공합니다. 브라우저의 Canvas 읽기·메모리 할당·이벤트 스케줄링은 이 예산으로 보장할 수 없습니다. 계산 중 픽셀 편집과 저장을 잠그고, 완료할 때 변경 경계의 이전/이후 픽셀을 한 번 기록합니다. 오류/취소가 발생하면 미확정 픽셀을 기록하지 않습니다.

최악의 Undo 픽셀 용량을 할당 전에 확인하며 기존 128 MiB 히스토리 한도를 적용합니다. 원본/참조/계산 버퍼·큐·마스크는 히스토리와 별도 임시 메모리입니다. 현재 캔버스 최대 크기와 레이어 한도는 그대로입니다.

## 검증

개발 중 새 9개 기능 검사, 수정한 도구 전환/허용 오차 검사 및 기존 프리셋/숫자·선택/클립보드·지우개 관련 검사를 우선 실행했습니다. 포커스가 남은 숫자 입력창의 도구 전환 동기화를 수정했고, 겹쳐 그린 반투명 선의 모서리 알파(192)도 허용 오차 검사에 반영했습니다. 반복 부하는 점/작은 원 25회, Undo/Redo 8회, 레이어 5개 등 기존 정책을 유지합니다.

- 최종 `npm run build`: TypeScript 검사·Vite 프로덕션 빌드·서비스 워커 생성 성공. 초기 앱 109.01 kB(gzip 36.12 kB), PSD Worker 별도 지연 로딩 유지.
- 최종 `npm test -- --reporter=line`: 기존 66개 + 새 9개 = **75개 모두 통과**, 약 **2.0분**, 자동 재시도 없음. 최종 전체 회귀는 한 번 실행했습니다.
- 새 검사: 네 도구 독립 값·슬라이더/숫자/키보드·새로고침, 색상 교환/초기화·히스토리 불변·색상과 무관한 지우개, 도구 세트 전체 관리·그림 보존·v1→v2·오류 보호.
- RGB 선택 미리보기/취소·알파/완전 투명 픽셀·선택 밖/다른 레이어 보존·단일 Undo/Redo, 닫힌 영역·선택 제한·비인접·허용 오차별 반투명 경계·확장·현재/전체 보이는 레이어 참조·가이드/흰 배경 제외·다른 컷 격리 검사 통과.
- 512×512 분할 계산 도중 이벤트 루프의 취소 요청을 처리하고 픽셀/히스토리를 보존하는 검사, 채우기 후 프로젝트 재열기·IndexedDB 새로고침 복구 검사 통과. 기존 자유 변형·PSD·원본 JSON 및 `.mpaint` v1/v2·오프라인 검사도 통과했습니다.
- 기존 반복 브러시 표본: 히스토리 7.375 MiB, 최대 렌더 작업 약 3.40ms, 평균 이벤트 처리→렌더 약 0.91ms. Linux Chromium 소프트웨어 환경 표본이며 디스플레이/실제 펜 지연·FPS 보장값이나 환경 간 성능 동등성을 증명하는 수치는 아닙니다.
- 페인트통 옵션과 실제 채우기 결과의 화면 스크린샷을 확인했습니다.

Windows 실제 펜·브라우저 저장 권한·하드웨어 표시 지연은 별도 수동 검증 대상입니다.
